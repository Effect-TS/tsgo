# Using tsrs in place of typescript-go

Effect Go code reaches typescript-go through the generated shim packages in `shim/<pkg>`
(`github.com/microsoft/TypeScript/tsc/shim/<pkg>`, generated by `_tools/gen_shims`). They re-export the provider's
`internal/<pkg>` and add accessors for unexported members (`_tools/gen_shims/config/<pkg>/extra-shim.json`, and the
hand-written helpers in `_tools/gen_shims/providers/<provider>/<pkg>/integration.go`).

The Rust port reaches tsrs only through the generated `ets_shim` crate: `ets_shim::<pkg>` re-exports the tsrs crate
that ports `internal/<pkg>` (the crate map is `tsrs/porting/PORTING.md`, "Layout") plus whatever `_patches/tsrs`
exposes. This file records how each shim API maps to tsrs, so each mapping is worked out once. Add a row whenever you
map one that is not obvious. Re-verify the rows against the current tsrs pin when you use them (tsrs's API moves).

In the tables, `tsrs_<x>::...` names the tsrs item; Effect code writes it as `ets_shim::<x>::...`.

## Finding the tsrs equivalent

1. Get the Go name the shim aliases: `shim/<pkg>/shim.go` (or `extra-shim.json`, `integration.go`). For example
   `checker.Checker_getSymbolOfDeclaration` is the unexported `(*Checker).getSymbolOfDeclaration`.
2. tsrs keeps Go's names, snake_cased: `rg -n 'fn get_symbol_of_declaration\b' tsrs/crates`. Each tsrs function has
   an origin marker (`// checker.go:1234`), and `tsrs/docs/sigs/*.txt` indexes the checker's signatures. Constants,
   statics and the associated constants of Go's enum-like types are SCREAMING_SNAKE_CASE, as tsrs's
   `tools/lib/rust-names.mjs` derives them from Go's name (`lsproto.CodeActionKindQuickFix` is
   `CodeActionKind::QUICK_FIX`, `core.ScriptTargetESNext` is `ScriptTarget::ES_NEXT`,
   `diagnostics.Cannot_find_name_0` is `CANNOT_FIND_NAME_0`); bitflags keep Go's names (`SymbolFlags::ValueModule`).
3. Visibility tells you whether you can call it. `pub` is callable (add it to `ets_shim` if it is not re-exported
   yet). `pub(crate)` means it is unexported in Go: see "API gaps" in `PORTING.md` and "Gaps" below. Go's exported
   checker API (`exports.go`, `services.go`) is usually a `*_exported` method in tsrs when the unexported version
   also exists.

## The API path (programs in tests and the baseline runner)

This is the path `ets_effecttest` uses.

1. **File system**: `Arc<dyn FS>` = `Arc::new(tsrs_vfs::bundled::wrap_fs(tsrs_vfs::vfstest::from_map(files, true)))`.
   The Effect packages are mounted as `internal/bundledeffect` / `vfstest.MountEffect` do.
2. **Config**: a `'static` `ParseConfigHost` over that FS, then
   `tsrs_tsoptions::get_parsed_command_line_of_config_file("/tsconfig.json", None, None, host, None)`; `P::new(config)`.
3. **Host**: `tsrs_compiler::new_cached_fs_compiler_host(cwd, fs, &bundled::lib_path(), None, None, None)`.
4. **Program**: `ProgramOptions::new(config, host)`; for a program that will be freed: `checker_regions = true`,
   `checker_diagnostic_regions = true`, `regions = Some(Arc::new(ProgramRegions::default()))`;
   `tsrs_compiler::new_program(opts)`.
5. **Checker**: `program.get_source_file(name)`, `program.get_type_checker_for_file(&Context::background(), file)`
   (a `CheckerHandle`: drop it before anything else takes the same checker, e.g. the file's semantic diagnostics,
   or it deadlocks).
6. **Release** (Go: the GC): drop every `CheckerHandle` and everything derived from the program (copy strings out
   first), then `unsafe { tsrs_compiler::free_unshared_program(program) }`, then drop the `Arc<ProgramRegions>`.
