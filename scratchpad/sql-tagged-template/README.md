# Typed SQL tagged-template spike

This separate compiler spike builds on [the Effect SQL draft](https://github.com/Effect-TS/effect/pull/9780).
The compiler preserves template segments, and a small adapter reuses that draft's
public `SqlClient.Query` type for SQL validation, row inference, and parameters.

```ts
import * as Effect from "effect/Effect"
import * as SqlClient from "effect/sql/SqlClient"
import schema from "./_schema.json" with { type: "json" }
import { tagged } from "./tagged.ts"

class Database extends SqlClient.Service<Database>()("Database", { schema }) {}

const findUsers = Effect.gen(function*() {
  const sql = tagged(yield* Database)
  const minimumAge = 18
  return yield* sql`
    SELECT id, name, email FROM users WHERE age >= ${minimumAge}
  `
})
// Effect.Effect<
//   readonly { readonly id: number; readonly name: string; readonly email: string | null }[],
//   SqlError,
//   Database
// >
```

`minimumAge` must be a number. Unknown tables, unknown columns, and interpolated
identifiers are rejected. Interpolated values remain bound SQL parameters.
The runnable [`main.ts`](./main.ts) migrates an in-memory SQLite database and
queries it with the exact tagged-template syntax.

## Compiler change

Enable the experimental option in the consuming project's `tsconfig.json`:

```json
{
  "compilerOptions": {
    "plugins": [{
      "name": "@effect/language-service",
      "experimentalLiteralTemplateStrings": true
    }]
  }
}
```

For a call such as ``sql`SELECT id FROM users WHERE age >= ${age}```, the checker
normally supplies `TemplateStringsArray` as the first argument. The patch supplies:

```ts
TemplateStringsArray & readonly ["SELECT id FROM users WHERE age >= ", ""]
```

The substitution remains a separate expression with its original type and source
location. This enables ordinary generic inference in both CLI checks and language
server hovers. JavaScript emission and the runtime template object are unchanged.
The compiler contains no SQL grammar and does not transform `.ts` source files.
Editor hovers require this patched tsgo language server; stock TypeScript does
not recognize the option.

[`tagged.ts`](./tagged.ts) joins the literal segments with generated `:p0`, `:p1`,
etc. placeholders at the type level, then instantiates the existing public
`SqlClient.Query` signature. At runtime it supplies the matching parameter object
to that same query constructor. It does not import Effect internals or duplicate
the SQL parser.

`tagged` is prototype library glue. Its signature and implementation could become
a tagged overload on `SqlClient.Query`, allowing `const sql = yield* Database`
directly. This spike keeps the existing Effect draft unchanged.

## Run

Use Node 24 or later and the repository's pinned pnpm version. First prepare the
compiler in this checkout:

```sh
pnpm install
pnpm setup-repo --version 7.1.0-beta
go build -o tsgo ./typescript/tsc/cmd/tsc
```

In a separate Effect checkout containing PR #9780, install and build its references:

```sh
pnpm install
pnpm --filter scratchpad sql:check
```

Then, from this tsgo checkout:

```sh
node scratchpad/sql-tagged-template/setup.mjs /path/to/effect-checkout
./tsgo -p scratchpad/sql-tagged-template
node scratchpad/sql-tagged-template/main.ts
node scratchpad/sql-tagged-template/verify.ts
```

Setup links the existing Effect packages and generates a local `tsconfig.json`
with their project references. All example source is tracked; only these local
links, configuration paths, and temporary verification files are ignored.

The snapshot is generated by `Migrator.runWithSnapshot`. After changing
`migrations.ts`, regenerate it with:

```sh
node scratchpad/sql-tagged-template/snapshot.ts
```

## Local timing comparison

`node scratchpad/sql-tagged-template/measure.mjs` compares 100 distinct typed
queries using parentheses (option off) and tags (option on) in the same compiler.
It checks the inferred fields, disables incremental compilation, performs two
warmups per form, then alternates the order of eight measured runs per form.
An optional first argument selects a different compiler executable.

Measured with this patch on tsgo `93fc061`, TypeScript beta `3e92363`, and Effect
`df7c415`, on an Apple M4 Max with macOS arm64 and Node 24.22.1:

| Query form | Median | Range |
| --- | ---: | ---: |
| Parentheses | 273 ms | 176–563 ms |
| Tagged template | 288 ms | 155–399 ms |

These runs overlapped repository validation builds and are too noisy to establish
a consistent performance difference. They compare the two consumer APIs, not
unmodified and patched compiler binaries. Broad compiler performance remains
unverified; this is an experimental spike.

## Scope

- The option is off by default and applies to all tagged templates in the project.
  More precise arguments can change overload selection, so this is experimental.
- Existing `TemplateStringsArray` tags remain callable. The `.raw` property keeps
  its normal type; only cooked segments become literal tuple elements.
- Invalid template escapes retain the standard argument type, since their
  cooked values are `undefined`. The typed SQL adapter consequently rejects them.
- SQL support has the same single-table `SELECT` and SQLite `STRICT` limits as
  the Effect draft. Use substitutions for values; handwritten named placeholders
  are rejected by the adapter.
- SQL validation reports at the template argument; ordinary substitution type
  errors report on the substituted expression. SQL-specific completions are not
  part of this spike.
