# Sync the Rust port with its upstreams

Two independent jobs. Do them in separate pull requests.

## A. Bump tsrs

The argument is the target tsrs commit (default: the latest `main` of `https://github.com/oxc-project/tsrs`).

### 1. See what changes

```sh
OLD=$(jq -r '.components.tsrs | to_entries | last | .value.gitHead' _packages/tsgo/upstream.json)
git -C tsrs fetch origin
NEW=$(git -C tsrs rev-parse <target>)
git -C tsrs log --oneline $OLD..$NEW
git -C tsrs diff --stat $OLD $NEW -- crates/
```

- Note whether tsrs moved its TypeScript snapshot (tsrs's `Cargo.toml`, `[workspace.metadata.typescript]`) and its
  toolchain (`rust-toolchain.toml`).
- List public API changes in the crates `ets_shim` re-exports: renamed or removed `pub` items, changed signatures,
  visibility changes (`pub(crate)` -> `pub` may close a gap in `porting/TSRS_API.md`; the reverse breaks us).

### 2. Bump and rebase the patches

1. Set the tsrs component's `gitHead` in `_packages/tsgo/upstream.json` (and its `typescript` dependency if the
   snapshot moved), and the workspace toolchain to tsrs's. When the snapshot moves, the override folders named
   after the old TypeScript `gitHead` (`_patches/typescript-<gitHead>` and
   `_tools/gen_shims/providers/typescript-<gitHead>`; convention in `_patches/typescript/README.md`) turn stale and
   `repoctl check` fails on them: delete them if `_patches/typescript` and the canonical shims apply to the new
   TypeScript, otherwise rename both to the new `gitHead` and re-make what no longer applies (see the README of the
   patch override folder).
2. `pnpm exec repoctl submodules setup --component tsrs`: resets `tsrs/` to the new commit and applies `_patches/tsrs/*.patch` in order. For each patch
   that fails: re-make it against the new tsrs (the same change in the new code, nothing more), keeping its number,
   name and header. Drop a patch the new tsrs already carries (say so in the PR). Never fix a conflict by widening
   a patch.
3. `ets_shim` is regenerated by the same tsrs setup (`pnpm setup-repo` does not touch it: it removes `tsrs/`). If its generator config names items tsrs removed or renamed,
   update the config (never the generated crate).

### 3. Adapt the Effect crates

- `cargo build --all-targets` and fix every break by following `porting/TSRS_API.md`: update the mapping row, then the
  call sites. Changes in Effect crates must stay faithful to the Go: a tsrs rename changes the call, not the logic.
- Revisit `porting/TSRS_API.md`, "Gaps": a gap the new tsrs closes means the Rust-only helper or visibility patch can go
  (switch to the public API and delete the helper and its row).
- If tsrs moved its TypeScript snapshot: the Go comparison build moves too (the `typescript` entry the tsrs
  component depends on). Recheck every `typescript` row of `porting/DIVERGENCES.md`; remove the ones that disappeared,
  and prove any new difference before recording it.

### 4. Check and land

`cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test` (the baseline runner with
`--checkerAssignment go`), `pnpm exec repoctl tsrs port-check`. In CI the Validate tsrs workflow runs
`repoctl tsrs port-check`, then `repoctl tsrs lint|check|test` (the same cargo steps, after `--component tsrs`
setup). A baseline that newly fails is a regression from the bump:
fix it (`fix-parity`) in the same PR: there is no allowlist. One PR, titled
`chore: bump tsrs <old7>..<new7>`, listing the patches re-made or dropped and the API changes handled.
`repoctl tsrs port-diff` is not needed here: no Go code changed.

## B. Catch up with Go changes

Normally every PR that changes Go updates Rust in the same PR (`port-change` skill). Use this when that didn't
happen for a range (a large upstream TypeScript bump, an urgent fix merged without Rust, or a long-lived branch).

### 1. See what changes

```sh
pnpm exec repoctl tsrs port-check                   # marker hash mismatches, unknown markers
pnpm exec repoctl tsrs port-diff <oldRef> <newRef>  # removed / moved / changed / added declarations, with port status
git diff --stat <oldRef> <newRef> -- _patches/typescript _packages/tsgo/upstream.json shim _tools/gen_shims
```

`<oldRef>` is the last commit where `repoctl tsrs port-check` passed (CI history of the Validate tsrs workflow, or
`git log -G '// go( test)?: ' -- crates` for the last commit that acked markers).
Only rows whose status is `ported` need Rust work; `skipped` rows need their reason re-read; `require_new` is on, so
added rows must be ported (or skipped with a reason) now.

### 2. Port the changes

In this order, keeping each step buildable:

1. **`_patches/typescript` changed**: mirror every change into each `_patches/typescript-<gitHead>/<same name>`
   override folder (the patch backported to that TypeScript, e.g. the one the pinned tsrs ports, so the Go build
   compared with the Rust one has the same behavior; `repoctl check` enforces the same file names). For each changed
   or new Go patch that has (or now needs) a tsrs counterpart, make the same change in
   `_patches/tsrs/<same number and name>.patch`; for a removed Go patch, remove its tsrs and override-folder
   counterparts. Update `porting/TSRS_API.md`, "tsrs patches".
2. **Shim API changed** (`_tools/gen_shims` config or providers): update the `ets_shim` generator config to match. A
   change to `_tools/gen_shims/providers/typescript/` is also mirrored into the self-contained
   `providers/typescript-<gitHead>/` copies where it applies (the beta one).
3. **Removed** declarations: delete the Rust items (and their tests), and anything only they used.
4. **Moved**: move the Rust item to the file mirroring the new Go file, then `pnpm exec repoctl tsrs port-fix-lines`.
5. **Changed**: read the Go diff (`git diff <oldRef> <newRef> -- <file>`) and apply the same change to the Rust,
   faithfully. Don't re-port from scratch unless the declaration was rewritten. Then
   `pnpm exec repoctl tsrs port-ack <path> <Name>`.
6. **Added**: in ported packages, port them (as `port-package` does) and ack.
7. **Tests and baselines**: update ported tests from changed `_test.go` files; new or changed test cases and
   reference baselines come from the Go side and are used as is.

With many changes, split by package and dispatch `port-change` / `port-package` agents with the diff rows as their
brief, the way `port-next` does.

### 3. Check and land

Same gates as A.4. One PR, titled `port: catch up <old7>..<new7>`, with counts per diff section.
